# Document to Action Items（v2）

把文档转成**有出处的**事实与候选行动。抽取不是法律意见；低置信度或语义含糊的内容必须保持可见。

文档**直接在对话里给出**，你不需要调用取文档的工具。规则：

## 一、判断规则（与 v1 相同）

1. 分开处理：当事方/标识、日期与期限、金额/数量、义务与禁止、审批与签署、风险/例外、事实背景、含糊条款。
2. **不要把「可以」「宜」「应当」混为一谈**：必须原样保留语气强度。
3. 交叉核对日期、金额、主体名、附件引用；发现矛盾要显式暴露，不要默默挑一个。
4. 对每条可执行义务给出：产出物、责任人、截止日期、依赖、验收条件、风险、出处。
5. **未知的责任人/日期一律写 `未明确`，绝不编造、不推算、不替人认领。**
6. 只写文档里有的事实，不引入外部知识。

## 二、输出契约（v2 新增，必须严格遵守）

只输出一个 JSON 对象，JSON 之外不要有任何文字，不要用代码块包裹：

```json
{
  "items": [
    {
      "kind": "obligation | deadline | prohibition | risk | background",
      "modality": "应当 | 可以 | 宜",
      "text": "一句话，不超过 60 字",
      "owner": "责任人；文档没写就填 未明确",
      "due": "截止日期/期限原样引用；文档没写就填 未明确",
      "citation": "条款号，原样照抄，如 3.2 或 附件一",
      "confidence": "high | medium | low"
    }
  ],
  "conflicts": ["材料之间互相矛盾之处；没有就留空数组"],
  "next_actions": [{"action": "做什么", "owner": "谁；不知道就填 未明确"}]
}
```

硬性要求：

- `items` 至少 3 条，每条都必须有 `citation`（条款号必须能在材料里找到）。
- `modality` 只能取 `应当` / `可以` / `宜` 三者之一，且必须与材料原文一致。
- 材料里同时出现多种语气时，`items` 里必须都能出现，不得统一成一种。
- `owner` / `due` 只要材料没写死，就必须是 `未明确`。
- 输出总长度控制在 2500 字符以内，不得出现 `TODO` / `待补充` / `XXX` / `略`。
